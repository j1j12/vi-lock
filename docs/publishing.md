# GitHub 提交与发布检查

## 仓库边界

只在本目录初始化 Git，不在父工程或原 `versions` 仓库中操作。
本次未修改原仓库暂存区，不创建远端、不提交、不推送。推荐先创建私有仓库做人工复核。

```powershell
git init -b main
git config --local core.autocrlf false
python -B tools/check_repository.py
git add .
git diff --cached --stat
git status --short
# 人工审查通过后，再执行：
git commit -m "chore: import current development source baseline"
```

`.gitattributes` 固定文本 LF；原工作区/历史归档不受影响。
提交时 Git 可能规范化文本，因此导入清单 SHA256 是“复制时来源证据”，不是后续每次检出的哈希承诺。
Linux 执行脚本可显式使用 `sh`/`bash`，或在评审后设置必要脚本的 Git 可执行位。

## 上传前必须确认

- 不存在私钥、真实证书、PIN、人员模板、照片、事件数据库、客户信息。
- 本工具只能做基础扫描，不能代替人工安全审查；私网 IP 和旧机器路径是部署默认值，不应当作可直接使用的配置。
- 核对第三方许可证及原创代码发布授权，见 [许可说明](../THIRD_PARTY_NOTICES.md)。
- 无旧构建产物、模型权重、日志、归档包；不用 Git LFS 为不必要的构建垃圾兜底。
- 不在 README 把“独立测试通过”写成“整机最终验收通过”。

本快照保留业务源码不做隐式重构；旧源码旁部署文档未整批复制，以免带入失效归档链接和本机日志。
构建/部署请先读本仓库构建说明，再结合原本地历史资料审查，不能假设所有历史脚本适配新设备。
